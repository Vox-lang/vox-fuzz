# vox-fuzz v1 — Design

Date: 2026-08-17
Status: awaiting approval
Scope: fuzzing tool for code generated by the Vox compiler (Vox-lang/vox)

## Purpose

Vox's safety story is that all failure surfaces through compile-time
rejection or runtime error flags: out-of-bounds access sets an error flag
and returns 0; writes past a fixed buffer's end are refused; buffer
overflow is documented as impossible. vox-fuzz exists to attack that claim
mechanically.

## The invariant (what counts as a finding)

For any Vox program and any runtime input:

1. The compiler must not panic (no ICE).
2. The compiler's emitted assembly must be accepted by nasm and ld.
3. The emitted binary must never die by signal (SIGSEGV, SIGBUS, SIGILL,
   SIGFPE, SIGABRT, ...).
4. The emitted binary must terminate within the harness timeout.
5. Compiling the same source twice must produce identical assembly.

A **nonzero exit code is not a finding** — Vox programs exit nonzero
legitimately (`exit with code N`). Only signal deaths, hangs, ICEs,
toolchain rejections, and nondeterminism are findings.

No differential oracle in v1 (deliberate: deferred until the project owner
has evaluated the concept). The generator's AST (`grammar::Program`) is
the documented seam where a future evaluator plugs in.

## Architecture

Rust binary crate (edition 2024), GPLv3, CLI via clap. Two fuzzing loops
share one execution harness and one findings store.

```
grammar ──▶ render ──▶ [vox compile] ──▶ exec harness ──▶ classify ──▶ findings
   ▲                                        ▲                            │
 seeded RNG                              mutate (stdin/argv)          reduce
```

### Module: `grammar`

Typed AST of Vox constructs: variables, integer/decimal arithmetic,
comparisons, strings, dynamic and fixed buffers, lists, `while`/`for`
loops with ranges, `if`/`Otherwise` chains, functions (0–2 args), error
handlers (`On error`), `print`, `exit with code`, and stdin/argv reads.

Weighted random construction under a node-count budget, driven by a
seeded PRNG (`--seed`); a given (seed, generator version) pair always
yields the same program. Scope tracking ensures generated programs are
well-formed per the grammar (names declared before use, types tracked so
generation is valid by construction).

### Module: `render`

AST → English `.vox` text. This is the highest-risk module: Vox's block
structure (a nested construct's period does not close its parent; a blank
line closes the innermost open loop) must be reproduced exactly. The gen
loop doubles as its regression test: every generated program is expected
to compile, and the **compile-clean rate** is reported per run. A falling
rate signals renderer drift, not compiler bugs. Target: ≥95% of generated
programs compile.

### Module: `exec`

Shared harness for every child process (vox itself, nasm/ld via vox, and
the fuzzed binaries):

- Fresh temporary working directory per run — generated programs can
  legitimately open, create, and write files, so every run is caged in a
  disposable cwd inside the scratch area; nothing runs in the repo tree.
- rlimits via `pre_exec`: CPU seconds, address space, file size,
  `RLIMIT_CORE=0`.
- Wall-clock timeout with kill; SIGKILL after grace.
- Bounded capture of stdout/stderr (truncate beyond a cap).
- Classification: `Exit(code)`, `Signal(sig)`, `Timeout`.
- N parallel workers (`--jobs`, default = physical cores).

### Module: `mutate`

Input mutators for the `input` loop: bit/byte flips, boundary integers
(0, ±1, MAX, buffer-capacity ±1), block duplication/deletion/splice,
growth and truncation, non-UTF8 injection, and a token dictionary
harvested from the target's source strings. Corpus-based: seeds from
`--corpus` (defaults to built-in seeds; `vox/tests/` works as a corpus).

The mutation engine sits behind a trait so a coverage-guided backend
(e.g. AFL++ QEMU mode) can be added later without touching the loops.

### Module: `findings`

`findings/<category>/<id>/` containing: `program.vox`, input files/argv,
emitted asm (`vox --emit-asm` re-run), `classification.json` (category,
signal, seed, generator version, vox version, timestamps), and a
generated `repro.sh`. Categories: `ice`, `asm-reject`, `crash`, `hang`,
`nondeterministic`. Dedup key: category + signal + hash of normalized
program source; duplicates increment a counter rather than re-saving.

### Module: `reduce`

- Gen findings: statement-level pruning on the AST — remove subtrees,
  re-render, re-test, keep the smallest program that still reproduces.
- Input findings: chunk-removal and truncation passes over the input.

Reduction runs automatically on each new (non-duplicate) finding, budget-
capped so it cannot stall the fuzzing loop.

## CLI

```
vox-fuzz gen    [--seed N] [--count N | --forever] [--jobs N]
                [--timeout MS] [--vox PATH] [--out DIR] [--budget NODES]
vox-fuzz input  <target.vox|binary> [--corpus DIR] [--jobs N]
                [--timeout MS] [--vox PATH] [--out DIR]
vox-fuzz repro  <finding-dir>          # re-run a finding, report status
```

`--vox` defaults to `vox` on PATH, then `../vox/target/release/vox`.

## Testing vox-fuzz itself

- Renderer golden tests: fixed-seed ASTs → known `.vox` text.
- Renderer integration: generated programs piped through the real vox
  binary; compile-clean rate asserted in CI.
- Harness classification tests against crafted binaries (clean exit,
  nonzero exit, SIGSEGV, hang) built from tiny fixtures.
- Findings-store round-trip: classify → save → `repro.sh` reproduces.

## CI (GitHub Actions)

Build + clippy + unit tests; clone and build Vox-lang/vox; run the
renderer integration check and a fixed-seed ~2-minute smoke fuzz. A
finding during the smoke run fails the job and uploads the findings dir
as an artifact.

## Out of scope for v1 (seams documented)

- Differential/semantic oracle — plugs into `grammar::Program`.
- Coverage-guided fuzzing — plugs into the mutation-engine trait.
- File-channel input fuzzing beyond stdin/argv (planned as
  `--file NAME` in a later cut).
- Non-x86_64 targets.
